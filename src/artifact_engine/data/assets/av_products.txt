# av_products.txt -- where endpoint-security products keep their logs, and which
# reader (if any) this engine has for them. Read at run time by the
# `av_detections` parser; add your own lines freely, they survive upgrades.
#
# Format, one product per line, fields separated by `|`:
#
#   <product> | <reader> | <path> | <path> | ...
#
#   <product>  the name that lands in the `product` column
#   <reader>   the line reader to use, or `-` for none. A product with no
#              reader is still INVENTORIED: its paths, file count and date
#              window are reported, and report.txt says the logs were not read.
#              Point a rebranded or OEM product at an existing reader by naming
#              it here -- no code change needed when the format matches.
#   <path>     a path relative to the volume root. `*` globs one segment,
#              `%user%` expands to every user profile. Several paths per
#              product; each is reported separately.
#
# Readers that exist today: mcafee, symantec, msert. Everything else is an
# honest gap on purpose -- a half-parsed vendor log is worse than no reader,
# because it looks like an answer.
#
# The list mirrors KAPE's `Targets/Antivirus/*.tkape`, which is the living
# version of it; this file is a snapshot and the products shipped here are the
# ones whose paths were stable at the time. Windows Defender is deliberately
# absent: it has its own parsers (`defender_detections`, `evtx_defender`).
